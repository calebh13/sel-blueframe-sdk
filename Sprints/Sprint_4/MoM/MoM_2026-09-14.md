## 2. Key Discussion Points
- **Project Goal:**  
  The main goal for the semester is to find out whether a Python wrapper over the Go SDK is worth building and maintaining. Joe was clear that SEL does not want double maintenance. A Python port of the client would have to be kept in sync with the Go and C# clients by hand, so the Python side needs to wrap existing code instead of rewriting it.

- **Adaptability and Testing:**  
  The wrapper should be easy to adapt as the Go code changes. Joe expects testing harnesses to come out of the project, and AI tools can be used during development. The SDK itself should not be agentic, since paying for AI calls at runtime costs money and makes the tool less reliable.

- **Compatibility:**  
  The SDK should work across systems and ideally be OS-independent. How far that goes is still an open question for the team to investigate.

- **API Design and Documentation:**  
  Similar behavior should be grouped together in the API so engineers are not faced with dozens of near-duplicate calls. Documentation was a big point. Joe wants docs treated as a major part of the deliverable. A build script should also be part of the handoff.

- **Process:**  
  Test-driven development was suggested, along with an early preview of the Go wrapping to find problems sooner.

- **Risk:**  
  It is possible that the Go code does not work well inside an SDK at all. Finding that out early is part of the Sprint 4 work.

- **Sprint Plan:**  
  Sprint 4 is a planning period covering testing, the documentation framework, general processes, and goals. Sprint 5 needs to produce the Python bindings.

- **Open Questions Raised by the Team:**  
  Which Python version to hold constant, how multithreading will behave, how static the Go code is, what maintenance should look like, performance, how to test, OS dependence, and whether builtins would need to be remade.

- **Questions and Answers:**
  - *Genevieve asked how future developers would extend the wrapper.* Joe left this for the team to work out.
  - *Lucas asked which Python version to target.* Python 3.12, and Joe is open to suggestions.
  - *Genevieve asked whether SDK users should be kept away from the internals.* Yes, users should not have to see Go details. The team decides how.
  - *Genevieve asked about the main use case.* Publish and subscribe.
  - *Lucas asked about privacy and whether AI tools can be used.* AI tools are fine. SEL code should not be posted on the internet.
  - *Lucas asked what benchmarks and specs to aim for.* Joe asked the team to propose them.

## 3. Decisions Made
- The Python SDK will wrap existing SEL client code. There will be no Python port.
- Python 3.12 is the baseline version.
- Publish and subscribe is the primary use case.
- AI tools may be used during development, but SEL code stays off the public internet.
- Sprint 4 is for planning and investigation. Sprint 5 is for building the bindings.
